# Радар 3D-заказов

Радар читает Telegram-каналы и официальный RSS заказов FL.ru. Дополнительные зарубежные доски и Threads сохранены как выключенные источники. Система ничего не публикует, не отвечает заказчикам и только пересылает подходящие карточки владельцу в Telegram.

Нет автооткликов, генерации сообщений, OpenAI API, платных API, авторизации на биржах или браузерной автоматизации.

## 1. Что понадобится

- Windows и Python 3.14 (проверьте: `py --version`);
- Telegram-аккаунт-сборщик, вручную подписанный на нужные каналы;
- бот, созданный через `@BotFather`;
- API ID и API hash с [my.telegram.org/apps](https://my.telegram.org/apps).

Никому не отправляйте токен бота, API hash или коды входа — в том числе в чат Codex.

## 2. Виртуальное окружение и зависимости

Откройте PowerShell в папке проекта и активируйте созданное окружение:

```powershell
.\.venv\Scripts\Activate.ps1
```

Если PowerShell запрещает запуск скриптов только для текущего окна, выполните:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

После активации слева в строке будет `(.venv)`. Установите зависимости:

```powershell
python -m pip install -r requirements.txt
```

## 3. Настройка `.env`

Скопируйте шаблон и откройте новый файл:

```powershell
Copy-Item .env.example .env
notepad .env
```

Заполните:

- `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` — с сайта Telegram API;
- `BOT_TOKEN` — токен от `@BotFather`;
- `OWNER_CHAT_ID` — ваш числовой ID.

`SEND_JOB_VACANCIES=false` (по умолчанию) оставляет уведомления только для разовых заказов. Поставьте `true`, чтобы бот также присылал полноценные вакансии.

Чтобы узнать ID, временно оставьте `OWNER_CHAT_ID` пустым нельзя: защита намеренно не позволит старт. Удобный порядок: узнайте ID через бота `@userinfobot`, впишите его в `.env`, запустите систему и отправьте своему боту `/start`. Он подтвердит ID. Боту сначала нужно написать `/start` вручную в Telegram.

## 4. Авторизация аккаунта-сборщика

Это **единственный** скрипт, который спросит номер телефона и код Telegram. Запускайте его только сами в своей консоли:

```powershell
python authorize_telegram.py
```

После успеха рядом появится файл `collector.session` (или имя из `TELETHON_SESSION`). Он секретный и уже исключён из Git. Номер, код и пароль двухэтапной проверки никуда не пересылайте.

## 5. Узнать ID каналов

Аккаунт-сборщик должен быть заранее подписан на каналы вручную. После авторизации выполните:

```powershell
python list_dialogs.py
```

Скрипт выведет строки `ID`, название и username. Скопируйте первое число. Для каналов оно обычно начинается с `-100`.

## 6. Настроить `sources.json`

Откройте файл:

```powershell
notepad sources.json
```

Замените или добавьте объект, например:

```json
{
  "channel_id": -1001234567890,
  "name": "Моё понятное название",
  "username": "public_channel_name",
  "mode": "general",
  "enabled": true
}
```

`channel_id` — ID из `list_dialogs.py`; `username` — публичное имя без `@` или `null` для приватного канала. Значение `mode`:

- `general`: публикация нужна только с признаком 3D;
- `3d_only`: специализированный 3D-канал — принимаются даже пустые публикации и посты без ключевого слова.

Активные Telegram-источники должны быть доступны аккаунту-сборщику: заранее подпишитесь на них вручную. Сохраните корректный JSON: объекты разделяются запятыми, последней запятой нет. После изменения источников перезапустите программу.

## 7. Запуск и остановка

После заполнения `.env`, авторизации и настройки источников:

```powershell
python main.py
```

Остановить безопасно: нажмите `Ctrl+C` в том же окне PowerShell. Команды боту отправляйте только со своего аккаунта:

- `/start` — подтверждает работу и показывает chat_id;
- `/status` — состояние и число активных источников;
- `/stats` — принятые, отклонённые, отправленные;
- `/pause` — не присылать новые карточки (они всё равно помечаются обработанными);
- `/resume` — снова присылать;
- `/sources` — активные источники;
- `/test` — тестовая карточка.

Другим пользователям бот ничего не отвечает и уведомления им не отправляет.

## Как фильтруются публикации

В общих каналах система ищет 3D, 3д, моделирование, визуализацию, рендер, STL/OBJ/FBX/GLB/GLTF, мебель/интерьер/экстерьер, archviz, UV, текстуры, 3D-печать, CNC, game-ready и другие признаки из `filters.py`. Blender не обязателен. Отсекаются видеомонтаж, озвучка, AI-видео, обычный графдизайн, предложения услуг/резюме, курсы, новости, реклама и продажа ассетов.

Сумма ниже 1000 ₽ отклоняется только если **точно известен максимум**: `500 ₽` и `до 800 ₽` — нет; `500–1500 ₽`, `от 500 ₽`, `1000 ₽`, договорная цена, неизвестная сумма или другая валюта — да. Размеры, сроки и полигоны без слов цены/валюты не являются ценой.

Каждый ID канала + ID сообщения записывается в SQLite, поэтому один пост не отправляется дважды. База также хранит счётчики.

## Типичные ошибки

| Симптом | Что сделать |
|---|---|
| `В .env не задано...` | Создайте `.env` из шаблона и заполните все 4 обязательных значения. |
| `Account not authorized` | Выполните `python authorize_telegram.py` сами и завершите вход. |
| `No module named ...` | Активируйте `.venv`, затем `python -m pip install -r requirements.txt`. |
| Бот не отвечает | Напишите боту `/start` в Telegram, проверьте токен и точность `OWNER_CHAT_ID`. |
| Нет новых карточек | Проверьте `enabled: true`, ID канала, ручную подписку аккаунта и перезапустите `main.py`. |
| Ошибка JSON | Проверьте запятые, кавычки и квадратные скобки в `sources.json`. |
| Нет ссылки на сообщение | Для приватного канала ссылка работает только у участников; оставьте `username: null`. |

## Проверка тестов

Без подключения к Telegram:

```powershell
python -m unittest discover -s tests -v
```

Также в `requirements.txt` указан `pytest`: если он установлен, можно выполнить `python -m pytest -q`.

## Круглосуточный запуск на Ubuntu VM (systemd)

Служба запускает тот же постоянный `main.py`: Telethon получает новые сообщения сразу после их появления, а systemd перезапускает процесс после сбоя. SQLite находится в `/opt/3d-job-radar/data/`, а `sources.json` — в `/opt/3d-job-radar/`, поэтому они сохраняются после рестартов и обновлений.

1. На локальном компьютере, где уже есть авторизованный `collector.session`, вручную выведите одноразовую строку сессии:

```powershell
.\.venv\Scripts\python.exe export_string_session.py
```

Не передавайте эту строку в чат и не сохраняйте в репозитории: она равнозначна паролю Telegram.

2. Скопируйте проект на Ubuntu VM безопасным способом (без `.env` и `collector.session`), войдите на VM и из корня проекта выполните:

```bash
sudo bash deploy/install_server.sh
```

3. Создайте секретный файл вручную и вставьте значения из `deploy/job-radar.env.example`:

```bash
sudo nano /etc/3d-job-radar/job-radar.env
sudo chown root:3d-job-radar /etc/3d-job-radar/job-radar.env
sudo chmod 640 /etc/3d-job-radar/job-radar.env
```

Используйте `TELETHON_STRING_SESSION`, а `DATABASE_PATH` и `SOURCES_PATH` оставьте указанными в шаблоне. Серверный скрипт не создаёт этот файл и не запускает авторизацию Telegram.

4. Включите службу и проверьте её:

```bash
sudo systemctl enable --now 3d-job-radar
sudo systemctl status 3d-job-radar
```

Диагностика и управление:

```bash
sudo systemctl start 3d-job-radar
sudo systemctl stop 3d-job-radar
sudo systemctl restart 3d-job-radar
sudo systemctl status 3d-job-radar
sudo journalctl -u 3d-job-radar -n 100 --no-pager
sudo journalctl -u 3d-job-radar -f
sudo systemctl enable 3d-job-radar
```

Безопасное обновление: остановите службу, сохраните резервную копию `data/orders.sqlite3` и `sources.json`, загрузите новую версию проекта, повторно выполните `sudo bash deploy/install_server.sh`, затем запустите `sudo systemctl start 3d-job-radar`. Не заменяйте `/etc/3d-job-radar/job-radar.env`.

Для проверки Telegram-соединения используйте логи после запуска: `sudo journalctl -u 3d-job-radar -f`. Успешное подключение выводит строку о запуске и количестве активных источников; секреты в логи не попадают.

## Пассивный режим GitHub Actions

`run_once.py` предназначен для запуска из `.github/workflows/job-radar.yml` каждые 5 минут. Telegram проверяется при каждом запуске, а FL.ru — не чаще одного раза в 15 минут. При первом запуске Telegram только запоминает текущие ID сообщений; FL.ru рассматривает свежие публикации не старше 72 часов. Затем GitHub Actions коммитит только файлы состояния; SQLite, сессии, `.env` и секреты не сохраняются в репозитории.

Добавьте в GitHub Secrets: `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELETHON_STRING_SESSION`, `BOT_TOKEN`, `OWNER_CHAT_ID`. Не запускайте `run_once.py` вручную на локальном компьютере с рабочими секретами, если не хотите выполнить реальную проверку Telegram.

## Главный внешний источник: FL.ru

Радар читает официальный RSS FL.ru отдельно для категорий «3D-графика» и «Разработка игр». Логин, пароль и аккаунт FL.ru для чтения не нужны. Из RSS извлекаются точная дата, название, описание, бюджет, категория и прямая ссылка на заказ.

```env
FLRU_ENABLED=true
FLRU_POLL_INTERVAL_MINUTES=15
```

За один опрос отправляются максимум три лучших новых результата. Сначала идут игровые props/hard-surface/game-ready, STL/FDM, модели по фото/чертежам/размерам, Blender и GLB/GLTF. Персонажи, существа, риггинг, полные игровые окружения, Motion/VFX, инженерные расчёты и задачи с обязательными Maya/3ds Max/Corona/SolidWorks не отправляются.

## Threads — выключенный экспериментальный источник

Для Threads используется только официальный read-only API Meta и разрешение `threads_keyword_search`. Источник по умолчанию выключен: текущий API возвращает нестабильные ошибки, поэтому он не участвует в рабочем поиске. Если доступ будет подтверждён, добавьте долгоживущий пользовательский токен в GitHub Secret `THREADS_ACCESS_TOKEN`; не помещайте токен в код, `.env.example`, логи или URL.

GitHub Actions выполняет шесть запросов `RECENT` каждые пять минут: `3D`, `3д`, `Blender`, `визуализатор`, `смоделировать`, `рендер`. Англоязычные публикации отбрасываются до общего фильтра. Затем остаются только посты с реальным намерением нанять исполнителя и конкретной 3D-задачей; самореклама, видеомонтаж, AI-видео, озвучка и точный бюджет ниже 1000 ₽ исключаются. ID уже просмотренных публикаций сохраняются в `state/external_sources.json`, поэтому один популярный пост не отправляется повторно.

Переменные запуска:

```env
THREADS_ENABLED=true
THREADS_ACCESS_TOKEN=long-lived-token
THREADS_POLL_INTERVAL_MINUTES=5
```

Долгоживущий токен Threads действует 60 дней после выпуска или обновления. Его нужно обновить до истечения срока.

## Отключённые общие доски вакансий

Himalayas, Jobicy и Remotive сохранены для диагностики, но по умолчанию выключены: контрольный поиск показал, что они дают преимущественно общие англоязычные вакансии, а не подходящие разовые 3D-заказы.

Настройки в `.env` (такие же значения есть в `.env.example`):

```env
HIMALAYAS_ENABLED=false
HIMALAYAS_POLL_INTERVAL_MINUTES=1440
JOBICY_ENABLED=false
JOBICY_POLL_INTERVAL_MINUTES=60
REMOTIVE_ENABLED=false
REMOTIVE_POLL_INTERVAL_MINUTES=360
```

Если источник включить вручную, `Himalayas` опрашивается не чаще раза в 24 часа, `Jobicy` — раза в час, `Remotive` — раз в 6 часов. Ошибка любого внешнего источника не останавливает FL.ru или Telegram.

Для внешних вакансий HTML очищается, затем объединяются название, короткое описание и полный текст, после чего применяется тот же строгий фильтр 3D из `filters.py`. Обычные Graphic Designer, UI/UX, Video Editor, маркетинг и чистый 2D не проходят. Настройки `SEND_FREELANCE_VACANCIES` и `SEND_JOB_VACANCIES` работают для этих источников так же, как для Telegram.

Состояние находится в `state/external_sources.json` и сохраняется GitHub Actions вместе с `state/last_seen.json`. На первом запуске каждый внешний источник рассматривает только объявления моложе 72 часов и отправляет не более трёх подходящих карточек. На последующих запусках рассматриваются только новые `external_id`; остальные новые публикации после ранжирования помечаются просмотренными и не создают шум. Дубли не отправляются повторно, старые записи состояния удаляются через 30 дней.

Для ручной проверки используются обычные команда и секреты Telegram, поэтому не запускайте её без намерения выполнить реальную проверку:

```powershell
.\.venv\Scripts\python.exe run_once.py
```

В GitHub Actions внешний контур запускается автоматически вместе с `run_once.py`; для FL.ru новые GitHub Secrets не нужны.

## Диагностическая проверка истории

`scan_history.py` читает последние публикации **только** включённых источников из `sources.json`, применяет тот же фильтр, что и основная система, и создаёт локальный `scan_report.txt` в UTF-8. Он не отправляет ничего боту, не открывает SQLite и не помечает сообщения обработанными.

После ручной авторизации аккаунта выполните, например:

```powershell
python scan_history.py --limit 100
```

Чтобы не выводить в консоль отклонённые публикации (они всё равно останутся в полном `scan_report.txt`), добавьте `--accepted-only`.

## Параллельный строгий русскоязычный режим

`strict_run_once.py` — отдельный контур с собственными источниками и файлом состояния. Он не импортируется существующими `main.py` и `run_once.py`, поэтому текущий бот и расписание GitHub Actions не меняются.

Источники задаются в `strict_sources.json`. Сейчас включены CG Freelance, CG Worker и «Вакансии 2D/3D Художники» (`artisthh`). FL.ru в строгом контуре отсутствует, потому что отклик исполнителя на площадке платный.

Перед отправкой обязательны все проверки:

- русский язык объявления;
- точная дата оригинала: до 72 часов для разового заказа, до 7 дней для вакансии;
- бесплатный прямой контакт или внешняя форма;
- отсутствие Europe-only, обязательного английского, зарубежной карты/счёта и запрета на работу из России;
- отсутствие конкурсов, revshare, волонтёрства, неоплачиваемых тестовых и закрытых объявлений;
- соответствие профилю Blender: предметы, hard-surface, low-poly props, STL/FDM и модели по фото, размерам или чертежам.

Безопасная диагностика истории не отправляет сообщения и не меняет состояние:

```powershell
python strict_run_once.py --dry-run --limit 50
```

Параллельный аудит обрабатывает только новые публикации, сохраняет статистику причин отказа, но ничего не отправляет:

```powershell
python strict_run_once.py --audit
```

Именно этот режим добавлен в существующий GitHub Actions после обычного запуска. Пятиминутное расписание, старый фильтр и его уведомления не меняются. Для включения строгих уведомлений после контрольного периода нужно убрать `--audit`; отдельное состояние не даст прислать накопленную историю.

Обычный запуск отправляет только прошедшие строгий фильтр публикации. При первом запуске он лишь запоминает текущую границу каждого канала, поэтому старая история не придёт пачкой:

```powershell
python strict_run_once.py
```

Статистика причин отказа и отдельные последние ID сохраняются в `state/strict_last_seen.json`.
